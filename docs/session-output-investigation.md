# 会话输出预览：本机日志验证

验证日期：2026-11-02，Asia/Shanghai。

## 结论

本机 Codex Desktop 的 JSONL 会话记录可以支撑“运行中的会话列表 + 最新完整输出 + 已完成工具结果”。中途发出的进度消息会在本轮任务结束之前写入，因此无需等待最终回答才能更新内容预览。

本次没有观察到回复文本的逐字增量。实测正文在单条消息生成完成后整体出现，不能把这条数据源承诺为与原客户端逐字同步。仅工具运行结束后的结果已验证；长命令运行过程中的输出增量未验证。

Claude 的历史日志包含正文和工具记录，格式具备接入条件；本机所检查的最近记录来自 2026-10-21，没有用活跃的 Claude 会话验证实时写入时机。

本节记录数据源验证过程，未修改客户端配置或安装 Hooks，也未创建新的模型请求。实现状态见文末。

## 可接入字段

| 内容 | Codex 实际字段 |
| --- | --- |
| 会话标识与项目目录 | `session_meta.payload.id`、`cwd` |
| 轮次开始 | `event_msg` / `task_started`，包含 `turn_id`、`started_at` |
| 可见正文 | `response_item` / `message`，`role=assistant`，`content[].type=output_text` |
| 正文阶段 | 当前版本使用 `phase=commentary` 或 `phase=final_answer`，不能只按 `channel` 解析 |
| 正文的另一份记录 | `event_msg` / `item_completed`，`item.type=AgentMessage`，与正文记录有相同消息 ID |
| 工具结果 | `item_completed` 中的 `CommandExecution`，或 `custom_tool_call_output`；后者需要关联调用记录 |
| 轮次完成 | `event_msg` / `task_complete`，包含 `turn_id`、`completed_at` |

两种正文事件需要按消息 ID 去重，或只采用其中一种。只展示可见正文和选定的工具信息；忽略推理记录、配置、系统消息等非展示数据。

Claude 的正文位于 `assistant.message.content` 中 `type=text` 的块；工具调用为 `type=tool_use` 的块，工具结果位于用户角色记录的 `tool_result` 块。应按内容块解析，避免将工具结果误判成用户新输入。

## 对首版的建议

1. Rust 后台维护独立的会话数据，与现有完成速度统计分开。按会话展示项目名、最近活动时间、最新完整回复与工具摘要。
2. 当前已验证的 Codex 使用轮次事件识别开始与完成；单条消息完成不等于整个轮次完成。缺少结束事件、客户端异常退出或只存在旧记录时，需要保留未知状态，避免把历史会话持续算作运行中。
3. 首次发现文件时回放必要状态，之后按字节偏移增量读取；处理半行、UTF-8 跨读取边界、截断和替换。结合目录监听与文件大小轮询兜底，避免每次遍历全部历史正文。
4. 按用户明确的展示要求，项目名与最新内容直接显示在现有速度监控条右侧，速度与曲线同时保留；长文本滚动，多个会话轮播或滚轮切换，不增加会话窗口。
5. 界面说明为“随会话记录更新”，不承诺逐字流式。后续如要求生成中的文字同步出现，再验证实际运行时接口或代理响应流。
6. Claude 实时行为单独验收；历史记录只能证明可解析，不能替代运行中实验。

观察脚本和仅含事件元数据的原始结果放在本地已忽略的 `scratch/` 目录：`session-feed-probe.py`、`session-feed-probe.json`、`session-feed-visible-probe.json`、`session-feed-live-proof.json`。

## 实现说明

后台 `sessions.rs` 按字节偏移读取两类 JSONL；每 750 ms 检查新增字节，每 5 秒发现新文件。首次读取保留头部元数据并回放至多最后 2 MiB；较早的轮次开始事件可能不在回放范围内，此时只标为近期活动，不宣称确认运行。单条日志、输出文本和历史条数均有上限。

Codex 明确轮次超过 10 分钟无更新、Claude 推断活动超过 2 分钟无更新时变为未知。内存快照保留最近一小时、最多 30 个会话，每个最多 60 条、每条最多 6000 字符；监控条展示最新内容的前 600 字符，悬停可读更多文字。前端已完成状态的展示时间与速度保留时间一致。

原生验证脚本 `scripts/check-sessions.py` 使用合成日志和隔离配置，验证同一监控条中的速度、曲线、输出、增量更新、半行、去重、滚轮切换与宽度设置；不需要调用模型服务。
